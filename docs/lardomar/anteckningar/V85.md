# Hästar – V85 (lärdomsfil)

Lärdomar för fliken Hästar, spelformen V85 (lördagar, ersätts av V75 från 2026-11-28). Data: `data/hastar/analys/<spel-id>.json` (analys + facit), `data/hastar/historik/<år>.jsonl.gz` (alla omgångar 2025–2026, slutstreck), modell `scripts/lib/trav-features.mjs` + `trav-weights.mjs`, system `gui/public/hast-engine.js`. Metod som för ligorna: en signal räknas bara om den slår **strecket** utanför träningsdatan, med |z| ≥ 2,5 och samma tecken båda halvåren.

**Kort sagt:** ATG:s öppna API ger alla hästars placering och km-tid i varje lopp. Med det räknas nu hur många meter efter vinnaren hästen var i sina senaste starter och hur snabb den var mot fältet. Men bakkörningen av V85- och V86-systemen 2025–2026 visar ingen förbättring (snitt antal rätt marginellt lägre, inom slumpen). Skrällarna bedöms inte bättre.

**Data:** `node scripts/hastar-lopp.mjs --hamta` hämtade 89 486 lopp (15 912 tävlingsdagar, de 3 senaste starterna för alla hästar 2021–2026, cirka 3 timmar i 9 anrop/s). Historiken saknar lopp-id, så loppet hittas via kalendern (datum + bana) och häst-id/namn. ### 2026-10-04: automatisk hämtning, läget "Utdelning" och skrällsystemet (658 omgångar 2023–2026)

**Kort sagt:** Datorn hämtar nu V85/V75/V86/GS75 automatiskt kl. 10, 2 h, 45 min och 15 min före start (Windows-uppgiften "Betting hastar auto") och följer upp tre system på strecket före start. Läget **Utdelning** (välj systemet med högst förväntad utdelning) **fungerade inte**: modellen överskattar hur mycket långskotten är värda när åtta avdelningar multipliceras. **Skrällsystemet** (minst 3 skrällar per rad) höll i den nya bakkörningen och har fått en egen knapp i webben, men det är fortfarande inte säkert.

**Så läser du det här:** ROI = vinst delat med insats minus 1. "Utan 1/3" = ROI när den största/de tre största vinsterna räknas bort, alltså hur beroende resultatet är av enstaka storvinster. Modellen tränad per kvartal på lopp före kvartalet, slutstreck (något för snällt), ATG:s riktiga utdelning för alla vinstnivåer. Standard = webbens förval (Värdefokus Standard, högsta rad ≥ 50 000 kr).

|---|---|---|---|---|---|---|
| Standard | −9,7 % | −21 % | −26 % | 459 | 0 | −36 / +7 / −8 / −2 |
| Folkets streck | −39,8 % | −44 % | −47 % | 474 | 0 | – |
| Utdelning | +3,0 % | −28 % | −44 % | 305 | 1 | −13 / +14 / −54 / +85 |

500 kr: standard +2,9 % (utan största −19 %), utdelning −8,5 %, skrällsystem +70 % (utan största +28 %, utan 3 största −38 %; −26 % år 2026). 200 kr: skrällsystemet −55 %, för få rader klarar villkoret. Bootstrap, chans att det egentligen är minus: skrällsystem 1 000 kr 17 %, 500 kr 23 %; standard 500 kr 42 %; utdelning 1 000 kr 46 %.

**Varför Utdelning missade:** modellens förväntade ROI var +121 % i de omgångar där den var som mest säker (409 st) men det blev −15 %. Den valde nästan alltid mest värdefokus (alpha 3) och fick färre vinster (305 mot 459 omgångar med vinst). **Beslut:**
1. Webbens förval ändras inte.
2. Knappen **Skrällsystem** (reducerat, utgång 16 ×, minst 3 skrällar per rad) finns i systembyggaren. Spela den på 1 000 kr eller mer. Siffrorna bygger på 5–6 storvinster på 658 omgångar, så räkna med långa perioder utan vinst.
3. Uppföljningen (`data/hastar/uppfoljning.json`, i webben "Uppföljning på riktigt") rättar standard, utdelning och skrällsystem automatiskt på strecket före start. Utvärdera efter cirka 50 omgångar. Första omgången (V85 Boden 2026-10-03, streck kl. 10): skrällsystemet 477 kr på 500 kr, standard 0 kr, utdelning 60 kr.

### 2026-10-04: jaga storvinster – högsta rad-spärr och skrällsystem (658 omgångar 2023–2026)

### 2026-10-04: skobyte räknas mot förra starten (felrättning)

**Fel:** `skorAv` räknade varje skobyte där hästen var barfota fram eller bak som "skor av", även barfota runt om → skor bak (Readly Brodde, spik i V85 Boden, 76 % chans, tvåa på nos). 3 886 starter 2021–2026 hade skor *på* men fick plus som "skor av". De vann 0,92 × strecket. Från barfota runt om till skor: streck < 35 % vinner 0,83 × (z −4,5, n 9 054), streck ≥ 35 % 0,88 × (z −2,7, n 488).

**Rättat:** `shoeChange()` i `trav-features.mjs` jämför med förra startens skor (finns i 77 % av bytena). Utan dem räknas bara säkra fall: barfota runt om = av, skor runt om = på. Kommentaren i analysen säger nu "Skor på (ändrat)" / "Skor av (ändrat)". Tester i `tests/hastar.spec.ts`.

**Rullande test 2021–2026 (kvartalsvis, 21 100 lopp):** bättre i 14 av 22 kvartal, diff −0,00004 per lopp, z −0,19, alltså i praktiken lika. Vikten för skor av blir renare (0,048 → 0,060) och skor på något svagare. Felet gällde för få starter för att märkas i snittet, men det kan avgöra enskilda spikar. Rättningen behålls eftersom den är korrekt och inte sämre. Vikterna i `trav-weights.mjs` lärs inte om nu (de är nästan desamma). Gör det vid nästa `hastar-lar.mjs`.
